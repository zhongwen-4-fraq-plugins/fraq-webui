# Briefing — fraq-webui

## Conventions

- 每次代码改动都要提交到 git。
- commit 说明格式：gitmoji（https://gitmoji.js.org/）+ [改动部分] + 改动摘要（最好十字以内）。
  - 改动部分示例：docs（文档）、core（核心）、add（新增）、remove（删除）等。
- 项目代码要简洁，偏向新手：简单直白优先，避免花哨技巧和过度抽象。
- 实现模糊功能时先向用户询问具体框架，并给出一些提示/建议选项。
- 代码编写按分类组织：数据处理、数据模型、服务、核心等。
