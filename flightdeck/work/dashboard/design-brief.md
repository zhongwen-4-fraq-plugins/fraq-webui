# Dashboard 设计简报 — fraq-webui

确认日期：2026-08-06。结构草图精度，规划已完成，待实现。

## 1. 功能摘要

给 fraq 实例的运营者/开发者提供一个轻量的 Web 管理界面：一眼确认机器人状态（概览），管理插件，查日志，配置连接与访问令牌。Vue 3 + Vite，浏览器优先。

## 2. 核心用户动作

打开页面，10 秒内判断"机器人是否正常、有没有需要处理的事"——状态异常、插件故障、日志报错都能立刻看到并顺路处理。

## 3. 设计方向

- 色彩策略：Restrained——纯白背景 + 一个天青色主色（seed：oklch(0.650 0.100 200.0)），语义状态色（成功/警告/错误/信息）只在状态处出现，不用来装饰。
- 场景句：运营者在白天于办公桌前打开浏览器，快速确认机器人一切正常——浅色、安静、一眼可扫。
- 锚点：nonebot-flutter-webui-dashboard（分区清晰、直白操作入口）、Linear（组件一致、熟悉即信任）、Vercel dashboard（运营面板的信息密度与克制）。

## 4. 范围

结构草图精度；覆盖整个界面外壳 + 概览/插件/日志/设置四屏；本轮只规划，不写代码。

## 5. 布局策略

- 应用外壳：左侧栏（概览 / 插件 / 日志 / 设置）+ 顶栏（实例名、连接状态、核心启停快捷操作）。
- 概览 = 三块而非卡片墙：核心状态区（运行中/已停止、连接地址、在线时长）、插件健康摘要（正常/异常计数 + 异常项直链）、最近日志摘录（带级别色点，点击进日志页）。
- 插件 = 列表 + 行内操作（启停、卸载、配置），不用卡片格。
- 日志 = 单列流，支持级别过滤、搜索、自动跟随；错误行高亮。
- 设置 = 分组表单（Milky 连接、访问令牌、安全选项）。
- 窄屏：侧栏折叠为顶部导航/抽屉，列表变纵向堆叠。

## 6. 关键状态

- 加载：骨架屏（状态区/列表骨架），不用中央转圈。
- 空态：无插件（提示如何安装）、无日志（"暂无输出，一切安静"）。
- 连接失败：顶部横幅 + 重试，概览降级显示"无法连接"。
- 核心离线：状态区醒目标识，启停按钮语义切换。
- 权限/未登录：访问令牌过期 → 跳登录，带 returnTo。
- 长日志/大列表：虚拟滚动或分页 + 加载更多。

## 7. 交互模型

- 核心启停：明确二次确认 + 进行中状态 + 结果反馈（成功/失败原因）。
- 插件启停/卸载：卸载需确认并说明影响；操作结果用 toast，失败可查日志。
- 日志：默认自动跟随最新，暂停跟随后可回溯；级别过滤即时生效。
- 状态轮询：概览定时刷新（如 5s），刷新时静默，不打断阅读。

## 8. 内容要求

- 全中文文案；状态词一致（运行中/已停止/连接失败/加载中）。
- 空态与错误文案承担"教用户下一步"的职责，不只是"暂无数据"。
- 动态数据：核心状态、插件列表、日志流；日志量级可能很大（数千行/小时），按需加载。

## 9. 实现时值得参考的规则

layout.md（外壳与层级）、harden.md（错误/空态/边界）、clarify.md（操作与报错文案）、adapt.md（窄屏折叠）。

## 10. 未决问题（实现层，不影响方案）

核心启停和插件管理需要一个管理接口——fraq 本身只提供协议 API（milky-server），没有"启停核心/装插件"的端点。实现时要定：由 WebUI 配套后端（调用 CLI/进程管理）提供，还是先只接 milky-server 能做到的部分（状态、日志、连接配置）。
